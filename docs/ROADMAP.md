# Red Companion — роадмап (v2)

GM-companion для Cyberpunk RED (Tauri: Rust + React). Основан на русской редакции книги правил (`docs/cyberpunkRedBook.pdf`, 458 стр.). Номера страниц — печатные.

> **Про исходный PDF.** Текстовый слой нечитаем (нестандартная кодировка шрифтов). Данные для справочников вносятся через OCR (Tesseract `rus`) с ручной вычиткой или вручную.

Приоритет: **В** — высокий, **С** — средний, **Н** — низкий.

## 0. Принятые решения

| Решение | Что это значит |
|---|---|
| **Бой абстрагирован до «Урон получен»** | Приложение не считает попадание, дальность, СЛ и режимы атаки. Мастер сам решил, что попали, и вводит результат в окно «Урон получен». Расчёт — от этого события |
| **Вход окна «Урон получен»** | Число урона (физические кубики) **или** бросок по нотации вроде `5d6` в приложении. Кубики видны → приложение само замечает две шестёрки и предлагает критическое повреждение; при вводе числа крит отмечается галочкой |
| **Укрытия — объекты сцены** | У укрытия есть ПЗ; несколько персонажей могут ссылаться на одно. Быстрые пресеты (живой щит, дерево, металл, бетон и т. д.), ПЗ можно менять. Укрытие **помнит своё ПЗ**, когда персонаж отходит и возвращается — оно уже подстрелено |
| **Данные пользователя локально** | Персонажи, NPC и сессии — в SQLite на машине мастера. Перенос между устройствами и игроками — экспорт/импорт файлом (версионированный JSON) |
| **Справочники — отдельный API** | Сервер (возможно Go) хранит справочники (NPC, оружие, броня и т. д.); пользователь может скачать их локально для оффлайна. Приложение сравнивает версии небольшим запросом и предлагает обновиться |
| **Доступ к API — через Rust-бэкенд Tauri** | Rust ходит в API, ведёт кэш и локальные базы; фронт получает данные командами Tauri. Для справочников есть один слой доступа (`DataSource`), сервер появляется в последней фазе |
| **Откладываем далеко** | Транспорт, нетраннинг, экономика, карта Найт-Сити, API-сервер и админка |

## 1. Механики и что с ними делать

### 1.1 Окно «Урон получен» (стр. 182–188) — ядро MVP

**Входные данные окна:**
- Урон: число или бросок (`NdM`), для кубиков — автоопределение двух шестёрок.
- Область: тело / голова; цель — предмет или нога (если прицельный выстрел).
- Режим брони: **полная**, **½ вверх** (ближний бой, боевые искусства), **игнорируется** (огонь, удушение, электричество, яд и т. д.).
- Модификаторы: голова + прицельный выстрел → прошедший урон ×2; автоогонь → вводится итоговый урон.
- Укрытие: выбрать объект сцены, за которым стоит цель (или «нет»).
- Критическое повреждение: авто из кубиков или галочка; травма — случайная (2d6) или выбранная вручную из таблицы тела / головы.

**Алгоритм в Rust-ядре:**
1. Если выбрано укрытие, его ПЗ поглощают урон; остаток идёт дальше. Укрытие с ПЗ ≤ 0 разрушено.
2. Эффективная ОС = лучшая ОС области (броня не суммируется), при ½ — половина вверх, при игнорировании — 0.
3. Прошедший урон = max(0, урон − ОС). Если >0, ОС этой брони уменьшается на 1 (абляция).
4. Голова + прицельный: прошедший урон ×2.
5. Крит: +5 урона мимо брони; бросок или выбор травмы, которой ещё нет у цели; травма добавляется к карточке.
6. Вычесть ПЗ, пересчитать состояние ранения; при смертельном — спасбросок от смерти в начале хода.
7. Вернуть полный лог шагов («почему получилось X») и применяемый результат; результат можно отменить.

## 3. MVP
Phase 0 + Phase 1: окно «Урон получен» с расчётом и логом, укрытия как объекты сцены с памятью ПЗ, лист персонажа с быстрым созданием и экспортом/импортом, трекер инициативы с состояниями ранения, критическими травмами и спасбросками от смерти. Справочники встроены в приложение — работает без сервера и интернета.

**Локализация.** Названия и описания — по ключам в `locales`; числа и правила — в данных без привязки к языку. Терминология русской редакции нестабильна («Сломанная нога» в тексте vs «Перелом ноги» в таблице; СЛ/DV вперемешку) — нужен глоссарий. Стат-аббревиатуры: РЕА=REF, ЛВК=DEX, ТЕЛ=BODY, ХАР=COOL, ЭМП=EMP, СКО=MOVE, УДЧ=LUCK, ПЗ=HP, ОС=SP.

## 6. Технические решения
- `rules-core` без зависимостей от Tauri: тестируется отдельно, переносится в WASM/сервер.
- Все броски через один интерфейс RNG; можно подставить значение с реальных кубиков.
- Данные справочников — только через `DataSource`; UI не знает, откуда они (встроенный снимок, кэш или API).
- Формат экспорта — версионированный JSON (`schema_version`), миграции при импорте.
- Результат применения урона можно отменить (история событий на сцене).

## 7. Права
Книга защищена авторским правом R. Talsorian Games. Перед публикацией справочников на сервере с таблицами и текстами из книги проверить условия Homebrew-лицензии RTG (не проверялось).

## 8. Пробелы

**Не читано или читано бегло:** создание персонажа и lifepath (71–98), ролевые способности (143–166), каталог киберимплантов (350–370), тексты большинства из 43 точек Найт-Сити (310–314), хронология (233–282), «Чёрный пёс» (435+), часть таблиц Чёрного ЛЬДа (207–208).

**В книге нет:** расстояний и сети дорог для маршрутов (карта схематична, без масштаба), рейтингов угроз по каждому району отдельно, статблоков большинства врагов (около десятка шаблонных NPC), вооружения и брони транспорта.
