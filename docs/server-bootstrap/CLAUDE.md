# Red Companion Server

Серверная часть десктопного GM-компаньона **Red Companion** для настольной игры Cyberpunk RED: API справочного контента для приложения, админка для его ведения и одностраничный сайт со свайпером на `https://red-companion.ru`. Приложение живёт в **другом репозитории**: `https://github.com/Hex1s/red-companion` (Tauri: Rust + React). Этот репозиторий: `https://github.com/Hex1s/red-companion-server`, владелец Hex1s.

**Главный документ — `docs/SERVER-SPEC.md`** (ТЗ, черновик № 5). Читай его перед любой крупной задачей; оттуда берутся модель данных, API, админка, этапы S0–S10. Если код расходится с ТЗ — не угадывай, спроси пользователя и после ответа поправь ТЗ.

## Контракт с приложением (не редактируется вручную)

- Структура записей определяется **Rust-типами приложения** (`crates/rules-core/src/catalog.rs`). Из них `cargo test` в репозитории приложения пишет `schemas/*.schema.json` и `schemas/hash-vectors.json`.
- В этот репозиторий файлы приходят скриптом синхронизации (или копией пакета, см. `README.md`) в `contracts/`: схемы, эталонные seed-данные `contracts/seed/{ru,en}`, векторы хэшей. **Не правь их руками**: исправление делается в репозитории приложения.
- Эталон для контрактных тестов — вшитые в приложение снимки (`contracts/seed`): импорт в чистую базу и выдача API должны вернуть тот же JSON. Хэши коллекций обязаны совпасть с `contracts/schemas/hash-vectors.json` (канонический JSON: ключи объектов отсортированы, записи упорядочены по `code`, затем `id`, затем `uuid`, без пробелов; SHA-256, hex в нижнем регистре).
- Правила валидации записей (диапазоны, `price > 0`, число слотов и т. п.) живут в Rust-валидаторах приложения (`validate_*` в `catalog.rs`) — **перенеси их в схемы/zod**, а не придумывай заново; справочный экземпляр — `reference/rules-core/catalog.rs`.

## Ошибки

Ошибки API — `{ code, params, message }`: `code` вида `domain.name`, `message` — английский для разработчика. Приложение переводит ошибки по `code`, поэтому **каждый новый код сервера** фиксируется в `docs/SERVER-SPEC.md` (раздел 6) и сообщается пользователю, чтобы он добавил перевод в приложение.

## Данные и лицензия

- Тексты записей — краткий пересказ своими словами, не копия книги. Лицензия R. Talsorian Games — на ответственности владельца проекта (решение 4 ТЗ); не добавляй в репозиторий полные тексты книги.
- Пользовательских данных на сервере нет и быть не должно (персонажи, сессии, заметки остаются у мастера). Сервер видит только токен установки, версию приложения, ОС и язык.

## Стек (по ТЗ)

Next.js (App Router) + TypeScript strict, PostgreSQL + Prisma, Auth.js (e-mail + пароль, argon2id, роли), zod, OpenAPI 3.1, React + Tailwind + shadcn/ui, Vitest + Playwright, Docker Compose + nginx + certbot на собственном VPS. Дизайн сайта и админки — «тактический HUD» приложения (тёмная тема, красный акцент `#d6302b`, шрифты JetBrains Mono и Tektur, срезанные углы, радиус 0, без градиентов и свечения).

## Порядок работ

Этапы S0–S10 из раздела 13 ТЗ. Начинать с S0 (каркас, CI, синхронизация контрактов), затем S1 (схема базы, импорт seed, хэши, ключ подписи) и S2 (API чтения с подписанным манифестом и регистрацией установок). Каждый этап заканчивается проверками и обновлением статуса в ТЗ; визуальные результаты (админка, сайт) смотрит пользователь.
