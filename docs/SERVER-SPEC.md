Документ описывает **отдельный репозиторий** (`red-companion-server`): API справочного контента для приложения, админку для его ведения и небольшой сайт приложения (лендинг, загрузки, changelog). ## 0. Контекст для сессии в репозитории сервера

Это ТЗ написано в репозитории приложения (`Hex1s/red-companion`), а сервер будет жить в **другом репозитории** (`Hex1s/red-companion-server`), где сессия Claude не видит файлов приложения. Поэтому нужное лежит в «пакете»: `python tools/export-server-bundle.py <папка сервера>` (после `cargo test --workspace`) копирует туда ТЗ, глоссарий, план данных, выдержку из роадмапа, `contracts/` (схемы, эталонные данные, векторы хэшей), справочные Rust-исходники и готовые `CLAUDE.md` и `README.md` сервера; подробнее — `docs/server-bootstrap/README.md`.

## 1. Цель и границы

**Цель:** заменить мок «ответа сервера» (`SeedDataSource` с языками, снимки `crates/rules-core/data/seed/{ru,en}`) настоящим сервером, не меняя ни ядро правил, ни интерфейс приложения: оно по-прежнему видит один слой `DataSource`. Заодно сервер даёт приложению обновления (контента и самого приложения) и становится «лицом» проекта в сети.

**Сервер отдаёт приложению:** серверный контент по решению 2.0 — укрытия, щиты, броню, оружие, модификации, боеприпасы, снаряжение, одежду, уличные наркотики, шаблоны NPC, роли, боевые искусства, подсказки специализаций (позже — транспорт, программы, имплантаты, районы); строки локалей; сведения о релизах контента и приложения.

**Сервер не отдаёт и не хранит:** ядро (таблицы критических травм, навыки, статьи правил, таблицы СЛ, таблицу магазинов, ценовые категории — вшиты в приложение и работают без сети), персонажей, сессии, заметки, энкаунтеры, портреты (всё это у мастера локально). **Пользовательские данные на сервер не попадают.**

**Чего на сервере нет (решение пользователя):** публичных справочников. Контент доступен только приложению (по ключу, раздел 6). Публичная часть — сайт приложения (раздел 9).

### 3.3. Общие поля записи

`uuid` (глобальный), `code`, `pack`, `name`, `summary` (где есть смысл), `source { page }`, поля контракта типа. **`code` уникален в типе и никогда не переиспользуется** после удаления: запись переводится в `retired`, код остаётся занятым (старые листы мастеров указывают на него). `uuid` не меняется при правках.

### 3.4. Что в `data`, что в `texts`

Всё, что мастер видит как текст, — в `texts` парами `ru`/`en`; остальное — в `data`. Текстовые поля сегодня:

| Коллекция | Текстовые поля | Нетекстовые (примеры) |
|---|---|---|
| `armor` | `name` | `sp`, `penalty`, `price` |
| `shields` | `name` | `hp`, `price` |
| `cover_materials` | `name` | `hp`, `thickness` |
| `weapons` | `name`, `examples`, `ammo`, `features[]`, `description` | `kind`, `skill`, `damage`, `magazine`, `rof`, `hands`, `concealable`, `price` |
| `weapon_mods` | `name`, `summary` | `price`, `slots`, `skills[]` |
| `ammo` | `name`, `usable_with`, `summary` | `price` |
| `gear` | `name`, `summary` | `price` |
| `clothing` | `name`, `tags` | `prices[9]` |
| `street_drugs` | `name`, `primary`, `secondary` | `price`, `duration_hours`, `secondary_dv` |
| `npc_templates` | `name`, `armor_name`, `gear`, `notes` | статы, ОС, `tier`, навыки со слагами |
| `roles` | `name`, `ability_name`, `summary`, `description`, тексты рангов и подспособностей | ранги, очки, лимиты |

Точный список полей — в `schemas/*.schema.json` приложения; сервер берёт его оттуда. Перечень текстовых полей типа — отдельная настройка типа (`textFields`): JSON Schema не отличает «строку-текст» от «строки-кода».

### 3.5. Проверка решения «одна таблица»

Пользователь согласился при условии, что всё на неё ложится. Проверено по задачам:

| Что нужно | Ложится? |
|---|---|
| Хэш коллекции (SHA-256 канонического JSON) | Да: хэш считается от записей в каноническом виде, а не от строк таблицы; хранение не влияет |
| Тексты парами и выдача на языке | Да: `texts` → плоский объект на запрошенном языке при сборке ответа |
| Форма админки, проверки, дифы | Да: из той же JSON Schema; новый тип = новая схема + `textFields`, без миграции |
| История правок, откат | Да: `EntryRevision` хранит `data` и `texts` как есть |
| Импорт существующих `seed` | Да: файлы уже лежат в виде «запись = JSON-объект» |
| Ссылки между записями (навык, травма, оружие) | Да, но **без внешних ключей БД**: проверяет валидатор публикации (раздел 8.3) |
| Поиск и фильтры в админке | Да: GIN-индекс по `data`/`texts` и обычные индексы по `collection`, `pack_id`, `state` |
| Быстрые запросы «оружие с уроном ≥ X» | Не нужны: публичного каталога нет, приложение читает коллекции целиком |

Что теряем: типизацию на уровне БД (ловит zod и контрактные тесты) и SQL-удобство для ad-hoc запросов (для них — `jsonb_path_query`). Для объёма в сотни записей это не стоит отдельных таблиц на тип.

## 4. Схемы и контракт с приложением

1. Источник правды по структуре записей — **Rust-типы** `crates/rules-core::catalog`; `cargo test` пишет `schemas/*.schema.json`. Сервер **копирует** их в `contracts/` (скрипт синхронизации) и строит zod-схемы.
2. Запись в ответе API — **ровно та структура, которую ждёт приложение**: плоский объект с полями типа, текстами на запрошенном языке, `uuid`, `code`, `pack`, `source`.
3. **Контрактный тест:** вшитые снимки приложения (`seed/ru`, `seed/en`) — эталон; импорт в чистую базу и выдача `GET` возвращают тот же JSON (с точностью до порядка ключей).
4. Манифест несёт `schema_version`; приложение отказывается от коллекции, формат которой новее понятного ему, и показывает «обновите приложение».

## 5. Версии, хэши, релизы, манифест

**Манифест есть с первого релиза** и отвечает на два вопроса: «нужно ли обновить справочник» и «нужно ли обновить приложение».

- **Релиз контента** — неизменяемый снимок опубликованных записей и локалей. Мастер всегда видит данные одного релиза; админка правит черновики и публикует новый релиз (раздел 8).
- **Хэш коллекции** = SHA-256 от канонического JSON записей коллекции **внутри пакета и языка** (ключи отсортированы, без пробелов, записи в порядке `code`). Язык входит в ключ.
- **Дерево:** `root` = хэш от хэшей пакетов; хэш пакета = хэш от хэшей его коллекций.
- **Подпись:** манифест подписывается **Ed25519**; приватный ключ — на сервере (секрет окружения), **публичный вшит в приложение** (его можно безопасно вшивать). Подмена сервера или ответа не пройдёт проверку (раздел 6.1).

```json
{
  "schema_version": 1,
  "content": {
    "release": 12,
    "root": "<sha256>",
    "min_app_version": "0.3.0",
    "note": { "ru": "Добавлены одежда и уличные наркотики", "en": "..." },
    "languages": ["ru", "en"],
    "packs": {
      "core": {
        "hash": "<sha256>",
        "counts": { "weapons": 29, "armor": 8, "gear": 53 },
        "collections": {
          "ru": { "weapons": "<sha256>", "armor": "<sha256>" },
          "en": { "weapons": "<sha256>", "armor": "<sha256>" }
        }
      }
    },
    "locales": { "ru": "<sha256>", "en": "<sha256>" }
  },
  "app": {
    "latest": "0.4.1",
    "min_supported": "0.3.0",
    "published_at": "2026-11-02T10:00:00Z",
    "changelog_url": "/api/v1/app/changelog?lang=",
    "update_url": "/api/v1/app/update/{target}/{arch}/{current_version}",
    "android": { "version": "0.4.1", "url": "/api/v1/download/android", "sha256": "<sha256>", "size": 31457280 }
  },
  "signature": "<ed25519>"
}
```

**Логика приложения:**

| Что в манифесте | Действие |
|---|---|
| `content.root` совпал с локальным | справочник актуален, ничего не делаем |
| `content.root` другой, `min_app_version` ≤ текущей | предлагаем «Обновить справочник» (+ «Посмотреть changelog» = `content.note` и список изменений), качаем **только изменившиеся** коллекции скачанных пакетов |
| `content.min_app_version` > текущей | справочник обновить нельзя: «Для нового справочника нужно обновить приложение» |
| `app.latest` > текущей | «Доступно обновление приложения» + «Посмотреть changelog» + кнопка «Обновить»: updater Tauri скачивает и ставит обновление сам, приложение перезапускается (раздел 10) |
| `app.min_supported` > текущей | обновление обязательно для работы с сервером; локальный режим продолжает работать |

- `ETag` ответа коллекции = её хэш; повторный запрос с `If-None-Match` — `304`.
- Алгоритм хэширования **одинаковый на сервере и в приложении**: в `rules-core` есть `Collection::content_hash`; общий набор тестовых векторов (вход → ожидаемый хэш) лежит в `contracts/`.
- Хэш говорит «изменилось», но не «что»; список изменений (добавлено/изменено/выведено) считается при публикации релиза и хранится вместе с ним.

## 6. API

Базовый путь `/api/v1`. Язык — `?lang=ru|en`; без языка `400` с кодом ошибки.

| Метод и путь | Доступ | Что отдаёт |
|---|---|---|
| `POST /installations` | публичный, с ограничением по IP | регистрирует установку, возвращает её токен (раздел 6.1) |
| `GET /manifest` | токен | подписанный манифест |
| `GET /packs`, `GET /packs/{pack}/{collection}?lang=` | токен | список пакетов и записи коллекции на языке; `ETag` = хэш |
| `GET /packs/{pack}/{collection}?lang=all` | токен | то же, тексты сразу на всех языках (полная выгрузка) |
| `GET /locales?lang=` | токен | ключ → текст; `ETag` = хэш языка |
| `GET /releases/{n}/manifest` | токен | манифест конкретного релиза |
| `GET /releases/{n}/changes?lang=` | токен | что изменилось в релизе (добавлено / изменено / выведено), для «Посмотреть changelog» |
| `GET /app/changelog?lang=&since=` | токен | changelog приложения |
| `GET /app/update/{target}/{arch}/{current_version}` | токен | **Windows и macOS:** ответ в формате **updater Tauri**: `{ version, notes, pub_date, url, signature }` или `204`, если обновления нет; файл подписан ключом updater (раздел 10). **Android** (`target=android`, `arch=universal`): `{ version, notes, pub_date, url, sha256, size }` или `204`; подписи minisign у APK нет, клиент сверяет `sha256`, а установку APK чужого ключа отклоняет сам Android |
| `GET /download/{platform}` | публичный | актуальный установщик с диска VPS (для первой установки с сайта); засчитывает загрузку (раздел 9) |
| `POST /ci/app-releases` | токен CI (`releases:write`) | CI загружает релиз: версия, changelog ru/en, файлы и подписи (раздел 8.2, п. 9) |
| `GET /openapi.json` | публичный | описание API |

**Ошибки** — в виде `{ "code": "domain.name", "params": {...}, "message": "<English for developers>" }`; приложение переводит по `code`. Коды: `server.bad_language`, `server.unknown_collection`, `server.unknown_pack`, `server.unauthorized`, `server.revoked`, `server.rate_limited`, `server.unavailable`.

**Админский API** (`/api/admin/...`) внутренний, под сессией Auth.js или `ServiceToken`, не стабилен.

### 6.1. Ключи и как их «зашить» (решение 2)

**Прямо: секрет, зашитый в приложение на компьютере пользователя, достать нельзя запретить.** Любой ключ в бинарнике можно вытащить отладчиком или просмотром трафика; обфускация только замедляет. Поэтому схема строится так, чтобы **в приложении не было ничего, что стоило бы вытаскивать**:

1. В приложение вшит только **публичный ключ подписи** (Ed25519) — для проверки манифеста. Это не секрет.
2. **Ключ — на установку, а не на приложение, и пользователь о нём не знает** (решение 10: ничего вводить не нужно). При первом запуске, в фоне, без окон и вопросов, приложение вызывает `POST /installations` (ограничение по IP, по умолчанию, скажем, 10 регистраций с адреса в сутки) и получает **собственный токен**; он лежит в SQLite приложения (или в хранилище ключей ОС) и отправляется в заголовке `Authorization: Bearer …`. Никакого общего ключа нет — нечего «слить» разом.
3. Что это даёт: учёт (число установок, версии, языки — это же счётчики для лендинга, раздел 9), ограничение частоты **на установку**, **отзыв** токена одной установки при злоупотреблении, невозможность массового скрейпинга одним общим ключом. Что не даёт: защиту от человека, который зарегистрирует себе токен вручную. Контент не секретен, цель — не пустить боты и считать установки, а не создать DRM.
4. Подлинность ответов даёт **подпись манифеста**: приложение принимает коллекции только с хэшами из подписанного манифеста; поддельный сервер или перехват трафика данные не подменят.
5. **Нет сети при первом запуске** — не ошибка: приложение работает на вшитом снимке, регистрацию повторяет при следующем запуске с сетью (мастер первого запуска не ждёт её).
6. Токен хранится в базе хэшем (`token_hash`); токены не логируются; смена токена при подозрении — повторная регистрация.

Если позже понадобится более жёсткая защита (платный контент и т. п.), добавляется привязка токена к машине и аттестация; в первую версию это не входит.

## 7. Тексты, локали и переводы

Решения пользователя (BOOK-PLAN, раздел 13), без изменений:

1. У каждого текстового поля записи в админке **два ввода**: «Текст ру» и «Текст en». Опубликовать запись с одним языком нельзя; пустой английский допустим только с пометкой «пока без перевода» (тогда `lang=en` отдаёт русский, запись помечена `fallback: true`).
2. **Локали живут в той же базе** (`Locale`); приложение держит вшитые `ru.json`/`en.json`, серверные строки накладываются поверх тем же механизмом хэшей (отдельная коллекция `locales`).
3. **Проверка парности при публикации:** ключ есть на обоих языках, набор `{{плейсхолдеров}}` совпадает (как `tools/check-i18n.mjs`), в `errors.*` нет пустых текстов.
4. Английский без английского издания: у записи пометка «неофициальный перевод», термины сверяются с `GLOSSARY.md`.
5. Тексты — краткий пересказ своими словами; над полем описания напоминание.

**Переводы делает Claude Code (решение 6).** Для этого сервер даёт, без ручного копирования:

- **Выгрузка «что нужно перевести»:** `GET /api/admin/translations/pending?lang=en` (и кнопка в админке) отдаёт JSON: список `{ entry|locale key, field, source_text (ru), current (en|null), context: тип записи, соседние поля, термин из GLOSSARY }`.
- **Загрузка переводов:** `POST /api/admin/translations` принимает тот же JSON с заполненным `text` и записывает **в черновик** (никогда сразу в релиз), помечая «машинный перевод, не проверено».
- **`ServiceToken` с областью `translations:write`** — токен для навыка переводчика: может читать «pending» и писать черновики переводов, **не может публиковать, менять числа и коды, удалять**. Все его действия попадают в `AuditLog` с именем токена.
- **Проверка человеком:** в админке фильтр «машинный перевод, не проверено» и кнопка «подтвердить»; публикация релиза показывает число непроверенных строк (предупреждение, не блокировка).
- Навык переводчика (инструкции для Claude Code: глоссарий, стиль, запрет копировать книгу) живёт в репозитории сервера в `.claude/skills/translate/` — отдельная небольшая задача (раздел 13, S6).

## 8. Админка

### 8.1. Роли

| Роль | Может |
|---|---|
| `owner` | всё: пользователи, токены, публикация релиза, откат, удаление, релизы приложения, настройки |
| `editor` | создавать и править черновики записей и локалей, не публиковать |
| `translator` | править тексты (один язык) и локали; не меняет числа и коды; к этой роли приравнен `ServiceToken translations:write` |
| `viewer` | читать (журнал, диффы) |

Первая версия — один владелец; роли закладываются сразу.

### 8.2. Экраны

1. **Вход** (e-mail + пароль, ограничение попыток, выход на всех устройствах; регистрации нет).
2. **Панель:** текущий релиз, число черновиков, непереведённых и непроверенных строк, непарных ключей, установок за последние 30 дней.
3. **Список коллекции:** таблица, поиск, фильтры по пакету и состоянию, колонки как в справочнике приложения.
4. **Редактор записи:** форма из схемы, **пары «Текст ру» / «Текст en»**, `code` задаётся при создании и затем не редактируется, страница книги; мягкие проверки при сохранении черновика, жёсткие при публикации; история и откат.
5. **Пакеты:** список, создание DLC, счётчики сущностей по типам (считаются сами).
6. **Локали:** таблица «ключ — ру — en», фильтры «не переведено», «машинный, не проверено», «непарные плейсхолдеры».
7. **Переводы:** выгрузка/загрузка файлом, токены переводчика.
8. **Релиз контента:** изменения с прошлого релиза, результат проверок, счётчики, поля «что нового» ru/en, кнопка «Опубликовать» (одна транзакция: проверки → снимок → хэши → подпись манифеста → запись `Release`). Откат = новый релиз с прежним содержимым.
9. **Релизы приложения** (только просмотр): список версий с changelog ru/en, `min_supported_version`, файлами и их `sha256`; кнопка «Отозвать релиз» (скрыть из манифеста и updater). Релизы **создаёт CI** (решения 11, 18, 19): пуш тега `vX.Y.Z` в `Hex1s/red-companion` запускает **GitHub Actions** с матрицей сборки:

   | Платформа | Что собирается | Где |
   |---|---|---|
   | Windows | установщик NSIS `.exe` + updater-пакет и подпись | `windows-latest` |
   | macOS | `.dmg` для первой установки + `.app.tar.gz` с подписью для updater; архитектуры `aarch64` и `x86_64` (или universal) | `macos-latest` |
   | Android | `.apk` (подписан своим ключом приложения), для планшетов | `ubuntu-latest` с Android SDK/NDK и JDK |

   Затем отдельный шаг читает changelog из `CHANGELOG.md` (разделы `ru` и `en` версии), собирает всё в один релиз и вызывает `POST /ci/app-releases` с токеном CI (`releases:write`, секрет репозитория). Сервер проверяет подписи и `sha256`, кладёт файлы в том `releases/`, создаёт `AppRelease` и обновляет блок `app` манифеста. Секреты репозитория: токен CI, приватный ключ updater, пароль и хранилище ключей Android (keystore), позже сертификаты подписи Windows и Apple (раздел 10).
10. **Настройки сайта:** ссылка на донат, текст «О приложении» (ru/en), контакты.
11. **Импорт:** JSON формата `seed/` с дифом перед записью.
12. **Журнал, пользователи, токены установок** (отзыв).

### 8.3. Проверки при публикации (жёсткие)

- каждая запись проходит zod-схему своего типа;
- `code` не пуст, уникален в типе, не занят `retired`-записью другой сущности;
- ссылки существуют (навык, травма, оружие, другая запись); ссылка на `retired` — предупреждение;
- оба языка у каждого текстового поля (или явная пометка «без перевода»);
- парность локалей и плейсхолдеров;
- числовые инварианты типа — **те же, что в Rust-валидаторах приложения** (диапазоны, `price > 0`, число слотов и т. п.), перенесённые в схемы типов;
- у записей основной книги есть `source.page`;
- `min_app_version` релиза не ниже версии, которая понимает все использованные форматы (`schema_version` схем).

## 9. Сайт приложения

**Один адрес, `https://red-companion.ru/`, одна страница, никаких отдельных страниц** (решение 15). Справочников нет (решение пользователя). Оформление — «в наших цветах»: тёмная тема, красный акцент, Tektur и JetBrains Mono, срезанные углы.

**Устройство.** На компьютере и планшете страница занимает **ровно один экран**; содержимое меняется **свайпером** (слайдами): горизонтальный свайп и перетаскивание мышью, колесо, стрелки и `Пробел` на клавиатуре, точки-индикаторы, подпись «что сейчас». У каждого слайда якорь (`/#roadmap`), чтобы на него можно было дать ссылку; браузерная «Назад» возвращает на предыдущий слайд. На телефонах свайпера нет: те же блоки идут подряд обычной вертикальной прокруткой с закреплённой кнопкой «Скачать». Учитывается `prefers-reduced-motion` (без анимации слайдов). Переключатель языка ru/en в углу; язык по умолчанию — по браузеру.

**Слайды (предложение, порядок можно менять):**

| # | Слайд | Что на нём |
|---|---|---|
| 1 | **Что это** | название, одна фраза (GM-компаньон для Cyberpunk RED), 3–4 главные возможности: «Урон получен» и укрытия, бой и инициатива, листы и шаблоны NPC, справочники; скриншот или короткая анимация интерфейса |
| 2 | **Для кого** | мастера (ГМ) Cyberpunk RED, что экономит за столом, что **не делает** (не считает попадание, мастер решает сам) |
| 3 | **В цифрах** | счётчики (ниже) |
| 4 | **Что нового** | последние версии приложения и релиз контента (ru/en), кнопка «Вся история» разворачивает список поверх слайда |
| 5 | **Роадмап** | этапы и статусы (готово / в работе / дальше), зашито в код |

| 7 | **Скачать** | кнопка для вашей платформы, версия, размер, `sha256` (раскрывается), системные требования, ссылка «политика данных» (короткая панель поверх слайда, что собирает сервер) |

Кнопка «Скачать» доступна **на каждом слайде** (в углу), чтобы не листать до последнего.

**Счётчики** (считаются на сервере, кэшируются на минуты):

- число загрузок (`DownloadEvent`, всего и по платформам);
- число активных установок за 30 дней (`Installation.last_seen_at`);
- число записей в справочнике по опубликованному релизу (всего и по типам);
- число языков и пакетов, номер релиза контента и дата;
- «**интересные значения**» из данных (решение: набор подтверждён, 6–8 штук, по несколько случайных на показ): самая дорогая вещь в базе; число языков для навыка «Язык»; суммарная стоимость всего снаряжения; число приёмов боевых искусств; число видов оружия и модификаций; сколько ролей и рангов описано; самая тяжёлая броня; число критических травм и СЛ их лечения. Набор — в коде слайда, меняется коммитом.

Роадмап и тексты слайдов лежат в репозитории (`content/`), правятся коммитом (решение 9), админки у них нет. Технически сайт — тот же Next.js-проект, страница рендерится на сервере; данные счётчиков берёт из тех же таблиц. Файлы `/download/{platform}` отдаёт тот же сервер.

## 10. «О приложении» и обновление приложения (для справки)

**Раздел «О приложении»** (репозиторий приложения): слово автора, для кого сделано, чьи переводы использованы, **ссылка на донат**, версия и кнопка «Проверить обновления». Тексты и ссылка на донат (**предложение**) приходят с сервера через `Setting` (`GET /api/v1/about?lang=`), с вшитым запасным вариантом на случай отсутствия сети.

**Обновление приложения (решение 13) — по платформам:**

| Платформа | Как обновляется | Что видит пользователь |
|---|---|---|
| Windows | updater Tauri (`tauri-plugin-updater`): скачивает пакет с VPS, проверяет подпись ключом updater (публичный вшит в приложение), ставит тихо (NSIS `passive`) и перезапускает | кнопка «Обновить» → прогресс → приложение перезапустилось |
| macOS | тот же updater (`.app.tar.gz`), приложение заменяется и перезапускается | то же |
| Android | **updater Tauri на Android не работает.** Кнопка «Обновить» скачивает новый `.apk` с VPS (проверка `sha256`) и открывает системный экран установки; система просит подтвердить один раз и разрешить установку из этого источника | кнопка → скачивание → системное «Обновить?» → «Да». Без подтверждения пользователя Android не ставит приложения; **полностью без касаний обновляет только Google Play** |

Пользовательские данные (SQLite, экспорт) лежат вне программы и обновление переживают. Подпись манифеста (Ed25519) и подпись updater (minisign Tauri) — два **разных** ключа; приватный updater-ключ лежит в секретах CI, копии ключей — в сейфе владельца. Потеря ключа updater означает, что на Windows и macOS придётся поставить новую версию вручную. Ключ подписи APK (keystore) терять нельзя совсем: с другим ключом Android не примет обновление поверх установленного.

### 10.1. Доверие к установщику (вопрос «как стать доверенным разработчиком»)

Доверие — это **подпись установщика сертификатом от доверенного центра** плюс репутация. Подпись самой программы вашим собственным ключом (updater, keystore) ОС за доверие не считает: она нужна, чтобы **обновления не подменили**, а не чтобы убрать предупреждения.

| Платформа | Что без подписи | Как стать «доверенным» | Цена и условия |
|---|---|---|---|
| **Windows** | при первом запуске установщика окно SmartScreen «Windows защитила ваш компьютер»: «Подробнее → Выполнить в любом случае». Работает, но выглядит подозрительно; обновления внутри приложения предупреждения не показывают | купить сертификат **подписи кода** (OV или EV) у центра сертификации; подписанный установщик получает «издателя», а SmartScreen со временем (по числу установок) перестаёт ругаться. EV раньше снимал предупреждение сразу, теперь это не гарантируется; репутация копится и у OV | примерно от 100 до 600 долларов в год; нужна проверка личности или организации; EV хранится на аппаратном ключе (в CI неудобно). Альтернативы: **Azure Trusted Signing** (около 10 долларов в месяц, ключи в облаке, удобно для CI, но доступен ограниченному кругу стран и форм регистрации), **SignPath Foundation** (бесплатно для **открытых** проектов с публичным репозиторием и OSI-лицензией). Условия и доступность в вашей стране нужно проверить заново |
| **macOS** | Gatekeeper не открывает приложение: «нельзя проверить на наличие вредоносного ПО»; обход — «Системные настройки → Конфиденциальность → Всё равно открыть» (на новых версиях и это скрывают) | **Apple Developer Program** (99 долларов в год): сертификат «Developer ID Application» + **нотаризация** (Apple проверяет сборку). После этого приложение открывается без предупреждений. Подпись и нотаризацию делает CI (секреты: сертификат, пароль, Apple ID/ключ API) | для регистрации нужен Apple ID, оплата картой и, в зависимости от страны, документы; в некоторых странах оплата недоступна — проверьте до планирования |
| **Android** | установка `.apk` «из неизвестных источников» требует разрешения в настройках; Google Play Protect может предупредить о неизвестном разработчике | **Google Play** (аккаунт разработчика, разовый взнос 25 долларов): приложение в магазине, обновления автоматические, предупреждений нет. Либо остаться на своём APK и объяснить пользователю разрешение | Play требует проверку личности и публикацию политики данных; в некоторых странах регистрация разработчика недоступна |

**Рекомендация по этапам (предложение):** первый релиз выпускаем **без** платных сертификатов: на Windows и macOS в README и на слайде «Скачать» короткая инструкция «как открыть, если система предупреждает», Android — APK с разрешением установки. Подпись покупается позже, когда будет видно, сколько у проекта пользователей; CI уже содержит места под секреты подписи, поэтому добавить её — вопрос ключей, а не переделки. Что решать сейчас, — выбор в разделе 15.
## 11. Клиент (для справки; работа идёт в репозитории приложения)

1. `ApiDataSource` реализует тот же трейт `DataSource`; UI о нём не знает.
2. **Тихая регистрация установки** при первом запуске (6.1, пользователь ничего не вводит) и хранение токена; подпись манифеста проверяется вшитым публичным ключом.
3. **Кэш** — таблицы в SQLite: ответ коллекции целиком + её хэш + язык + пакет + номер релиза.
4. **Запуск:** запрос манифеста; логика — таблица раздела 5. Сеть недоступна — работаем на кэше и вшитом снимке, ошибку не показываем (только при ручной проверке).
5. **Пакет скачан** и **включён** — два независимых состояния. Лист хранит `code`; если записи или пакета нет — код с пометкой «нет в базе».
6. **Языки:** кэш по `(пакет, коллекция, язык)`; ru / en / ru + en выбираются в мастере первого запуска (2.0b, 2.12).
7. **Локальные копии книжных шаблонов** (решения 7 и 16): копия показывается вместо оригинала, «сбросить» возвращает значения из книги. При обновлении оригинала копия не меняется. Копия запоминает хэш записи, от которой отделилась (`based_on_hash`, хэш канонического JSON записи — тот же алгоритм, что у коллекций; считается и для вшитых снимков, без сервера); если запись с тех пор изменилась, на копии метка «оригинал обновлён», а «сбросить» возвращает новую версию. Автоматического слияния нет. Это **задача приложения 2.22**, делается в первой версии и не зависит от готовности сервера.
8. **Режимы:** «запросы по мере надобности» и «скачать всё локально» используют один механизм хэшей.

## 12. Импорт данных, лицензия, безопасность, эксплуатация

**Импорт текущих данных (первый релиз):**

1. Скрипт `import-seed` читает `crates/rules-core/data/seed/{ru,en}/*.json`, склеивает пары `ru`/`en` по `uuid`/`code` (в обоих языках совпадают — это проверяет тест паритета приложения) и создаёт записи пакета `core` с **теми же `uuid` и `code`** (сохранённые листы и сцены на них ссылаются).
2. В базу идут только серверные коллекции (раздел 1); ядро остаётся в бинарнике.
3. Генераторы приложения (`tools/gen-*-seed.py`) остаются источником правды **до** запуска админки; после — источник правды база, а `seed/` превращается во вшитый снимок, обновляемый командой «экспорт релиза в формат `seed/`».
4. Контрактный тест (раздел 4, п. 3) подтверждает, что импорт и выдача дают тот же JSON.

**Лицензия RTG** — на ответственности владельца проекта (решение 4); шаблоны NPC и таблицы отдаются приложению. **(Предложение, не блокер):** держать на сайте и в «О приложении» короткую пометку о неофициальном материале и что тексты — пересказ.

**Безопасность:**

- пароли — argon2id; сессии `HttpOnly`, `SameSite=Lax`; CSRF-токены на изменяющих запросах; ограничение попыток входа; админка по отдельному пути (двухфакторный вход не нужен, решение 14);
- токены установок и сервисные токены хранятся хэшами, не логируются; регистрация ограничена по IP; IP в `DownloadEvent` — только хэш с солью;
- приватный ключ подписи манифеста и секреты — переменные окружения (не в репозитории); в секретах CI — ключ updater и токен CI; копии ключей в сейфе владельца: **потеря ключа подписи = перевыпуск ключа и обновление приложения вручную**;
- публичный API: только чтение + регистрация, ограничение частоты (по токену и по IP), кэш;
- журнал изменений неизменяем из интерфейса.

**Эксплуатация (свой VPS):**

- домен **red-companion.ru** (A-запись на VPS; **(предложение)** `www` → редирект на основной адрес); TLS — сертификаты Let's Encrypt, которые выпускает и продлевает **certbot** (контейнер рядом с nginx, проверка `http-01`, продление по расписанию и перезагрузка nginx без простоя); для писем Let's Encrypt и контактов нужен адрес владельца;
- Docker Compose: `app` (Next.js, порт наружу не публикуется), `db` (PostgreSQL, тоже только во внутренней сети), `proxy` (**nginx**: TLS, редирект `http` → `https`, HSTS, сжатие `gzip`/`brotli`, `client_max_body_size` с запасом под установщики (CI грузит файлы только на `/api/ci/`, остальным — малый лимит), `limit_req`/`limit_conn` для регистрации установок и входа в админку, кэш статики сайта и `/releases/`, отдача файлов из тома `releases/` напрямую через `sendfile` и `Range`, проксирование `/` и `/api/` на `app`), `certbot`, том `releases/` с установщиками и updater-пакетами (**на диске VPS**, решение 12; файлы небольшие), опционально `minio` позже (раздел 14);
- бэкап базы по расписанию (pg_dump → зашифрованный архив вне VPS), **проверка восстановления** раз в релиз; бэкап `.env` и ключа подписи отдельно;
- мониторинг: health-endpoint, логи в файл с ротацией, оповещение при недоступности;
- обновление: миграции Prisma в CI/CD, откат образа.

## 14. Отложено

- **Сервис картинок** (решение 8): S3-совместимое хранилище (готовый Docker-образ, например MinIO) на том же VPS, все изображения хранятся в WebP (приложение уже кодирует портреты в WebP, `src-tauri/src/portrait.rs`), в админке загрузка с автоконвертацией. **В первой версии картинок нет**, поэтому ни хранилища, ни полей `image` в схемах пока не вводим; когда появится место, где картинки нужны (иллюстрации записей, иконки оружия и т. п.), добавляем сервис отдельным этапом и поле `image` в схему типа.
